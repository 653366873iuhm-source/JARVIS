Inputs:
- SDK expectations: `sdk/src/api.ts` (spec written up in `sdk/API_CONTRACT.md`)
- Frontend expectations: `frontend/API_CONTRACT.md`
- Backend implementation: `backend/src/api/server.ts`. All routes are inline in this file, and `backend/src/api/routes/` is empty. Response shapes were read from `backend/src/services/{registration,market,promotion,rewards}.ts`.

Originally a review only. Fix-list items 1–4 have since been implemented (see **Status** under the fix list); the table below still describes the original gaps.

Result: **20 rows, 20 mismatches** (2 cross-cutting, 18 endpoints). None of the 18 client-expected endpoints works as-is: 4 are missing, and 14 exist under a different path or method, with different params or a different response shape.

## Status (items 1–4)

1. **Client `/v1`.** `sdk/src/api.ts` exports `DEFAULT_API_URL = "http://localhost:8080/v1"`, and `baseUrl` is now optional and defaults to it (before this there was no default). `sdk/examples/auto-agent/.env.example` uses `…/v1`. On the frontend, `.env.example`, `src/config.ts` defaults and `README.md` now use `VITE_API_URL=http://localhost:8080/v1` and `VITE_WS_URL=ws://localhost:8080/v1/ws`. The port also changed from 8787 to 8080, because the backend listens on `PORT=8080` (config, Dockerfile, compose).
2. **Error envelope.** `server.ts` sends `{ error: { code, message, details? } }` for `ApiError`, validation errors, fastify 4xx errors (such as a bad JSON body) and 500s. A new `setNotFoundHandler` returns `404 not_found` for unknown routes. Codes now match the MockBackend: `project_not_found` → `not_found` everywhere, and `bad_agent_id` → `invalid_agent_id`. The flat 403 `{status:"rejected",reason}` for #2 is still to be done with that route.
3. **Mappers.** The new `backend/src/api/mappers.ts` holds `toProjectSummary` and `toTrade`, plus `promotionStage` and `spotPriceWei`. `listProjects`, `projectDetail`, `projectTrades` and `recentTrades` (`/v1/trades/recent`) use them.
   - Project: `baseUri`→`baseURI`, `idx`→`index`, `createdAt`→`launchedAt`, `createdBlock`→`launchBlock` (string), `launchTx` (from the indexed factory `Launched` event), `sold`→`totalSupply` (string), `tokenPriceWei`→`spotPriceWei`, `reserveWei`→`reserveBnb`, `volume24hWei`→`volumeBnb24h`, `priceChange24hBps`→`change24hBps`, `marketCapWei`→`marketCapBnb`.
   - Project, added fields: `promotionStage` (derived from phase + `promotionStart` + window/max, matching `BondingNFT.promotionStage()`), `feeBps` (always the factory default 100, since it is not indexed per project), `collectionUri` (`<baseURI>collection.json`), `story`/`image` (null, since metadata is not fetched yet) and `updatedAt`.
   - Project, extras kept: `tag`, `nftPriceWei` (the old per-NFT `priceWei`), `volumeBnb`, `tradeCount`, `lastTradeAt`, `liveSupply`, `forcedGraduation`.
   - Trade: `txHash`→`tx`, `trader`→`wallet`, `ts`→`at`, `buy/sell`→`mint/burn`, `bnbWei`→`bnb`, `feeWei`→`fee`, plus `agentId`, and `name`/`symbol` on the ticker. Extras: `blockNumber` (string), `logIndex`, `firstTokenId`, `nftPriceWei`.
   - **Not yet mapped:** the WS `trade` payload (item 9), holders (#11) and candles (#12).
4. **`/projects`.**
   - New params: `phase` (400 `bad_phase` on an unknown value), `since` (keeps projects with `launchedAt >= since`), and `cursor` (opaque base64url offset; plain integers also accepted; 400 `bad_cursor`). `offset` still works.
   - Sort aliases: `new`→`created`, `volume`→`volume24h`, `mcap`→`marketcap`.
   - Default `limit` is 60 (max 100). The response adds `nextCursor`, which is null on the last page.
   - Detail adds `launcherHoldings`, `topHolders` (top 10 `{wallet,count}`) and `recentTrades` (20, Trade DTO).
   - Detail also adds `promotion`, which is null while trading. Otherwise it is `{shareBps, promoterCount, postCount, promoterRoot, attestations[]}`: `promoterCount` comes from the latest submitted attestation's promoter set, `postCount` counts gate-accepted posts, and `attestations` lists those with a tx.
   - Detail adds `firstPostGradId` (read from chain once graduated and cached; null before).
   - Detail still returns `lifecycle`, `tokensPerNft` and `maxCurveNfts`.
- **Candles `r.price`/`r.bnb`: not a bug.** The candle query selects `{ price: t.trades.priceWei, bnb: t.trades.bnbWei, … }`, so `r.price` and `r.bnb` are aliases of the right columns. The e2e candle assertions pass. The remaining #12 work (`tf`, BNB numbers, average fill price, bare array) belongs to item 7.

## Status (items 5–6)

All five SDK routes live in `src/api/routes/sdk.ts` (`registerSdkRoutes(app, ctx)`, wired with one call in `server.ts`). Responses use checksummed addresses, as the MockBackend does.

5. **Registration.**
   - `POST /v1/agents/register-request` is a state machine over `createChallenge` / `verifyRegistration`. Request state is stored in the `kv` table under `regreq:<agentId>|<wallet>`, so there is no schema change. The `requestId` is `req_<challengeId>`.
   - Validation: 400 `wrong_chain` when `chainId` ≠ `CHAIN_ID`. 400 `invalid_agent_id` unless the agentId is lowercase and ends in `.ai`. It must be lowercase because the SDK signs the agentId exactly as given and checks that the server echoes it back unchanged.
   - Phase 1 is idempotent per `agentId|wallet` and returns the same challenge. The challenge is re-issued once it expires, keeping the same X code. A phase-1 call after `rejected`, or with a changed handle/intent before approval, starts a fresh request.
   - Phase 2 returns 400 `bad_challenge` on a challenge/issuedAt/expiresAt mismatch and 401 `bad_wallet_signature` if the EIP-712 `AgentBinding` (the stored typed data) does not verify. A valid signature sets `awaiting_x_proof`, then the full `verifyRegistration` runs, using `xProofTweetUrl` when given and otherwise an X search. The status stays `verifying` while it runs.
   - Outcomes: success sets `approved`. `x_post_not_found` / `bad_tweet_url` stay `awaiting_x_proof` with a `reason`. `agent_id_*`, `x_not_found`, `x_post_too_old`, `x_handle_taken`, `wallet_bound` and `agent_removed` set `rejected` with reason `"<code>: <message>"`. Unexpected errors are rethrown (500).
   - `GET /v1/agents/:agentId/registration-signature?wallet=` (wallet optional; the newest request for the agentId is used without it):
     - 404 `not_found` (envelope) when there is no request.
     - 403 flat `{status:"rejected",reason}`.
     - 202 `{status:"pending",requestStatus,retryAfter:5,reason}`. While the request is `awaiting_x_proof`, a poll re-checks X by search, at most every 10 s.
     - 200 `ready` with the contract fields plus `calldata`. The platform signature is re-signed from the agent row when the registry nonce has changed or the deadline is < 2 min away.
   - The legacy `/v1/register/challenge` + `/verify` routes are unchanged.
6. **Quote, promotion code, rewards proof.**
   - **Quote.** `GET /v1/projects/:address/quote?side=&count=` pins `getBlockNumber()` and reads `virtualBnb`, `virtualToken`, `totalSupply` and `feeBps` at that block. It quotes with `lib/curve.ts` (`quoteBuy` / `quoteSell`, same rounding as the contract) and returns the contract shape: mint `amount`=cost and `total`=cost+fee; burn `amount`=gross and `total`=net.
     - 400 `bad_amount` for a count that is not a positive integer, above the remaining curve supply (mint) or above `totalSupply` (burn).
     - 400 `bad_side`.
     - 404 `not_found`: checked in the DB, falling back to `factory.isProject` while the indexer lags.
   - **Promotion code.** `POST /v1/promotions/code` with `{project,wallet}`.
     - Errors: 404 `not_found` for an unknown project, 403 `not_registered` (on-chain `AgentRegistry.canTrade`), 403 `not_holder` (on-chain `balanceOf` = 0).
     - Response: `code` is the existing stable HMAC `promoCode`. `tag` is the project tag (`#AP_<SYM>`), `cashtag` is `$<SYM>`, and `requiredText` is `[tag, code]`. `rules` is a `string[]` that mirrors the gate (bound X account, tag+code, posted after promotion starts, one per agent, no near-duplicates, must hold).
     - `window` is `{opensAt: promotionStart, closesAt: graduatedAt ?? promotionStart+7200}`, or null while trading. `expiresAt` is `window.closesAt`, or now+24 h while trading.
     - `link` is `${PUBLIC_APP_URL}/p/<project>`. `PUBLIC_APP_URL` is read from the environment (default `http://localhost:5173`) and is not yet a `config.ts` key.
     - Extra: `xHandle`. The old `GET /v1/promotion/:project/code` is kept.
   - **Rewards proof.** `GET /v1/rewards/:wallet/proof` returns:
     - `rewards[]` from `rewardsFor`: `epoch` as a string, `amountWei`→`amount`, `rewardPool` on each item, plus extras `root` and `calldata`. Posted epochs only, claimed ones included with `claimed:true`.
     - `promoterExemptions[]`: one entry per project whose latest submitted attestation lists the wallet. `{project, root, proof}` come from `promoterProof`, and `claimed` is on-chain `isPromoter`.
- Tests: `test/unit/sdk-routes.test.ts` (pure mappers / state helpers) and `test/e2e/sdk-integration.test.ts`. The e2e test runs Hardhat, the real backend with mock X / Agent ID, and the TS SDK from `../sdk/src` over HTTP. It covers register-request edge cases (wrong_chain, invalid_agent_id, bad_challenge, bad_wallet_signature, 404/202/403), then five agents registered via `AgentPad.register`, launch, quote vs. local quote vs. actual cost, mint to sell-out, promotion code + 403s, gate → graduation, promoter exemption claimed via `rewardsProof`, and reward epoch claimed via `claimRewards`.

   - The old `{total, holders}` and `{interval, candles}` shapes are gone. `services/market.ts` `projectHolders`/`candles` are left in place and still used by the PGlite unit test. `flow.test.ts` holder and candle assertions were updated to the new shapes.
8. **New FE routes.**
   - `GET /projects/:addr/promotions` returns a `PromotionPost[]`, newest first, built from the stored `x_posts`. `verified` means the gate status is `accepted`, and the raw verdict is kept as a `status` extra. `holdings` is the current NFT count. `url` is `https://x.com/<handle>/status/<id>`.
   - `GET /projects/:addr/nfts?limit` (default 120, max 500) returns an `NftItem[]` sorted by tokenId descending. `image` and `rarity` are always `null`, because metadata and VRF traits are not indexed yet.
   - `GET /agents/leaderboard?range=24h|7d|all` (default `all`; 400 `bad_range`) is registered before `/agents/:query`.
     - Uses the FE formula per (agent, project) inside the window: sell net − buy total incl. fee, plus max(0, net NFTs bought in the window) × current per-NFT spot × 0.99.
     - `winRateBps` = projects with PnL > 0 / projects traded in the window. `launches` and `graduated` count launches and graduations inside the window.
     - `posts` counts the agent's posts in the window, excluding `duplicate_text`. `canLaunch` is the on-chain mirror.
     - Removed agents are excluded. Rows are sorted by PnL descending. Extras: `projectsTraded`, `range`.
     - The old `/v1/leaderboard` is unchanged.
   - `GET /agents/:query` takes a wallet or a `.ai` id and returns an `AgentProfile`.
     - `registered` = indexed on chain and not removed. `canLaunch`, `canTrade` and `expiry` come from the indexed on-chain state.
     - `holdings[]`: `valueBnb` = curve sell net (`quoteSell`) while trading or in promotion, and count × last per-NFT price once graduated (approximation: the pool is not indexed). `costBnb` = remaining average cost incl. fee.
     - `launches[]` uses the Project DTO. `pnl`: realised = sell net − average-cost basis; unrealised = value − remaining cost; total = realised + unrealised. `recentTrades` holds 20 trades with name/symbol. `onchainVerified` is `false`.
     - An unregistered wallet gets 200 `registered:false`, and an unknown agent ID gets 404 `not_found`.
     - **This replaces `GET /v1/agents/:wallet`.** The two parametric routes cannot coexist, so the profile also carries the old record's extras (`walletType`, `intent`, `onchain`, `removed`, `refCode`, `eligibility`, `lastQualifiedAt`). Checked to coexist with `POST /v1/agents/register-request` and `GET /v1/agents/:agentId/registration-signature`.
9. **WebSocket `/v1/ws`.**
   - `?project=` still sets the initial filter.
   - A client `{type:"subscribe", channel:"trades", project?}` replaces the filter: no project means all trades, and an invalid address gets an `error` message. The server acks with `{type:"subscribed"}`. `{type:"unsubscribe"}` stops trade pushes.
   - Trades are pushed as `{type:"trade", data: Trade}`, using the Trade DTO with `agentId`, `name` and `symbol`, in order.
   - `project` lifecycle messages are still sent, filtered the same way. The server sends `{type:"ping"}` every 30 s.
- **Also changed, so real responses match the FE types:**
  - Per-project `/projects/:addr/trades` now includes `name`/`symbol`.
  - `change24hBps` is never `null`. With no trade before the 24 h window, the baseline is the launch price, since the curve was untouched; this is computed in `services/market.ts` `change24`.
